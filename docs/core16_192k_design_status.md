# Core16 @ 192 kHz 高频近场模式 — 设计与实现状态

> 用途：答辩/评审材料与后续迭代依据。2026-07-12 全链路上板打通。

## 一句话结论（2026-07-12 更新）

Core16/192k **已全链路打通并上板验证**：免晶振（PLL2 245.76MHz / IC7
分频 10 → 24.576MHz 精确合成），参数页一键切换 Wide32@48k ↔
Core16@192k，双向切换实测 3-8 秒完成，4 片 PCMD3180 在 24.576MHz
BCLK / 6.144MHz PDMCLK（32×FS）下全部配置成功，16 通道全活，SRP
512 点 / 97 频点（4.1-40.1kHz）运行 21-39ms/帧。

**实验室待验证项**：
1. 192k 下解调噪声底约 -30dBFS（32×FS 抽取比 + 超声麦自噪声，属预期
   物理现象），安静房间里 SRP 质量门(0.12)偶尔仍会闪过假峰 —— 需要
   真实超声源（气体泄漏/40kHz 换能器）标定质量门与显示门限。
2. 远程只能用耳机发 18kHz（响应差），40kHz 全频段定位精度需实验室
   超声源实测。
3. 长时间运行稳定性（>1h 连续 192k）未压测。

以下为原始设计文档（2026-07-08），供背景参考。

## 双模式设计

| 项 | Wide32 @ 48 kHz（当前产品） | Core16 @ 192 kHz（设计就绪） |
|----|------------------------------|-------------------------------|
| 阵列 | 全部 32 麦 | 内圈 16 麦（每片 PCMD 4 通道） |
| 采样率 | 48 kHz | 192 kHz |
| TDM | 16 槽/总线 | 8 槽/总线 |
| BCLK | 12.288 MHz | 24.576 MHz |
| 帧长/NFFT | 256 / 256 | 512 / 512 |
| 分析频带 | 563–7875 Hz（bin 3–42） | ~4.1–40 kHz（bin 11–107） |
| 定位模型 | SRP-PHAT 远场 | SRP-PHAT + 近场假设（短基线） |
| 目标场景 | 语音/机械/通用 | 气体泄漏、超声放电、轴承早期故障 |

## 已在代码中落地的部分

- `app_mic_array.c`: 32 麦几何全表，含 `tdm_slot_192k_core`、`is_core16`
  标记；内圈 16 麦子集与槽位唯一性校验双模式通过。
- `pcmd3180.c`: `PCMD3180_ARRAY_MODE_CORE16_192K` 完整模式配置
  （192k、8 槽、通道掩码、Core16 上电方案、BCLK 推导）。
- `app_acoustic_imaging.c`: `GetDefaultConfig(CORE16_192K, ...)` 输出
  完整合法配置（512 点帧、bin 11–107、80/120 对），通过 `ValidateConfig`。
- 合成自测框架 `app_acoustic_synthetic.c` 模式无关，可直接用于 Core16
  算法离线验证。

## 未接通的环节（按风险排序）

1. **硬件时钟（最高风险）**：192k×8 槽需要 SAI BCLK 24.576 MHz；
   PDM 时钟在 192k 下超出 PCMD3180 内部时钟限制，设计文档要求外部
   低抖动时钟源。当前 PLL2 → SAI1 只配置了 12.288 MHz 路线
   （`sys.c`），且无运行时重配。
2. **采集路径**：`app_pcmd_capture.c` 槽数/帧长/DMA 尺寸/发布模式
   均硬编码 Wide32；`Init(mode)` 有模式参数但运行时拒绝非 Wide32。
3. **SRP 运行时**：`app_acoustic_srp.h` 上限（帧 256/NFFT 256/40 bin）
   与 `ValidateRuntimeConfig` 的 Wide32 门需扩展，工作区
   （`.SRP_FAST`/`.EXTRAM`）需按 512 点重算尺寸并重新评估 CPU 预算。
4. **服务与 UI**：服务层无 CORE16 路由；参数页无模式切换项（预留了
   显示字符串 "Core16-HF-Nearfield"）。

## 建议的实施顺序（若后续迭代）

1. 板级确认 192k 时钟方案（外部时钟 or PLL 重配 + 分频），示波器验证
   BCLK/FSYNC 8 槽时序 —— 硬件在环，1 天。
2. 采集路径参数化（槽数/帧长/DMA/发布），先做"仅采集"里程碑：
   16ch@192k 原始 dBFS 上屏 —— 1 天。
3. SRP 上限扩展 + 工作区重算 + 512 点 FFT 性能基准 —— 0.5-1 天。
4. 服务/UI 模式切换（复用现有场景切换的原子重启机制）—— 0.5 天。

总计约 2.5-3.5 天 + 硬件验证窗口。风险集中在第 1 步；第 2-4 步为
纯软件、可在现有验证框架内回归。
